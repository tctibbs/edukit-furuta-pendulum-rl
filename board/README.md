# Board code

The balance policy runs inside the stock firmware's 500 Hz loop on the NUCLEO-F401RE (Cortex-M4F, bare metal). This directory holds the firmware-independent part, the actor's forward pass and the observation pipeline. Neither allocates, performs I/O, or keeps state beyond the weights. [model-conversion.md](../docs/runbooks/model-conversion.md) covers the export and its verification.

## Files

| File | What it is |
|---|---|
| `policy.h`, `policy.c` | The actor. `policy_forward` returns the raw mean action; `policy_command` bounds it (`tanh` or clamp, per `POLICY_SQUASH_ACTIONS`) and scales by the acceleration bound. |
| `policy_weights.h` | Generated by `just board-export CHECKPOINT BOUND`, where BOUND is `--squash-actions` or `--no-squash-actions`: weights as `static const float` arrays, plus the trained action bound. Overwritten on export. |
| `policy_vectors.json` | Generated by the same export: 64 observation vectors, PyTorch's float32 actions for them, and the bound flag, so tests can catch a mismatched header/vectors pair. |
| `observer.h`, `observer.c` | The observation pipeline: two least-squares slope estimators over the quantized angles, and the assembly of `[cos(tilt), sin(tilt), pendulum_rate, rotor_angle, rotor_rate]`. |
| `test_board.c` | A host harness that pipes lines of input through either module and prints the constants it was compiled with. Not part of the firmware image. |
