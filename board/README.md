# Board code

The balance and swing-up policies run inside the supplied firmware's 500 Hz loop on the NUCLEO-F401RE (Cortex-M4F, bare metal). This directory holds the actor's forward pass, the observation pipeline, and the showcase carousel. Every module but `showcase_port_stm32.c` and the `test_*.c` harnesses is firmware-independent C99 that allocates nothing and performs no I/O. The tests in `tests/` compile those modules into the harnesses on the host. [model-conversion.md](../docs/runbooks/model-conversion.md) covers the policy export and its verification, and the firmware runbook's [mode `x` section](../docs/runbooks/edukit-firmware.md#mode-x-the-showcase-carousel) covers the showcase.

## Files

| File | What it is |
|---|---|
| `policy.h`, `policy.c` | The actor. `policy_forward` returns the raw mean action; `policy_command` bounds it (`tanh` or clamp, per `POLICY_SQUASH_ACTIONS`) and scales by the acceleration bound. `policy_forward_with` and `policy_command_with` do the same for a named `policy_t`, which carries its own bound and squash. |
| `policy_weights.h` | Generated by `just board-export CHECKPOINT BOUND`, where BOUND is `--squash-actions` or `--no-squash-actions`: weights as `static const float` arrays, plus `POLICY_SQUASH_ACTIONS`. The acceleration bound for modes `b` and `r` is `RL_ACCEL_BOUND_RAD_S2` in the firmware header. Overwritten on export. |
| `policy_vectors.json` | Generated by the same export: 64 observation vectors, PyTorch's float32 actions for them, and the squash flag. The flag lets tests catch a mismatched header/vectors pair. |
| `observer.h`, `observer.c` | The observation pipeline: two least-squares slope estimators over the quantized angles, and the assembly of `[cos(tilt), sin(tilt), pendulum_rate, rotor_angle, rotor_rate]`. |
| `test_board.c` | A host harness that pipes lines of input through the policy or the observer and prints the constants it was compiled with. |
| `policies/` | Generated by `scripts/export_showcase.py` from `config/showcase.yaml`: one header and one vector file per policy the showcase runs, each header a `policy_t` with the bound and squash its checkpoint trained with. Overwritten on export. |
| `showcase_table.h`, `showcase_table.c` | The showcase's entries in the order `config/showcase.yaml` lists them, each with its group, kind, hardware test, and policy. `showcase_table.c` is generated by the same script. |
| `showcase.h`, `showcase.c` | The showcase's logic: the button's debounce and hold, the buzzer's tunes, one attempt's statistics, the selector that walks the table, and the result text. Also the LQR entry's gains, `SHOWCASE_LQR_*`. |
| `showcase_screens.h`, `showcase_screens.c` | The OLED screens. Each is worked out as text in a `showcase_screen_t`, then drawn. Every draw returns the number of characters that did not fit. |
| `showcase_probe.h`, `showcase_probe.c` | The hardware tests' measurements, a sample at a time from running sums: the swing meter (suspended-mode frequency and Q_eff at the release amplitude) and the base-tilt fit. |
| `display.h`, `display.c`, `font5x7.h`, `font5x7.c` | The SSD1306 framebuffer with text, bars, and dots, and the 5x7 font, whose 0x7F is a degree sign. |
| `showcase_port.h`, `showcase_port_stm32.c` | The board-specific glue on the STM32 HAL: the blue button and the buzzer from SysTick, the OLED on I2C1. Linked only into the mode `x` image. |
| `test_showcase.c` | A host harness for the showcase, its sounds and screens, the display, the generated table, and each table policy's forward pass. |
| `test_probe.c` | A host harness for the hardware tests' measurements. `tests/test_probe.py` feeds it [Experiment 03](../docs/experiments/03-hardware-bringup/writeup.md)'s captures. |
